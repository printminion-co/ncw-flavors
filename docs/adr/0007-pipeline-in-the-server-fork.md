# The pipeline lives in the server fork

The build, snapshot, candidate, sync and commit-lint workflows are `ionos-*.yml` files in the server fork, kept as `IONOS(ci)` commits in the patch series, and the fork's default branch is the live line's `ionos-dev-v<nn>`. A snapshot then freezes its own pipeline, so an old release rebuilds with exactly the workflows it shipped with, and no cross-repo token is needed. We considered keeping the workflows in the flavors repo, which leaves the fork closer to upstream but needs a token with write access to the fork and cannot freeze the pipeline with the release. The costs: the default branch is not `master`, so it must be switched at cutover; upstream's own workflows exist in the fork and must be disabled through the Actions API by the sync job, because deleting them would conflict on every rebase; and the workflow files are part of the series and are rebased with it.
