# One generated script does the occ work after install and upgrade

The deployment (Helm) must not carry logic that belongs to a flavor, and the flavor must stay testable in CI exactly as it is deployed. So the build generates `ncw-configure.sh` into every artifact. It imports the app configuration, sets the special settings and enables the apps the installer cannot enable (`enable_after_install`, needed for example for groupfolders, whose migrations fail inside `occ maintenance:install`). A deployment runs it with `bash` after install and after every upgrade; the smoke test runs the same file. The script needs only bash and the archive's `php occ`, and is idempotent. Alternatives were the same steps as `occ` calls in the Helm chart (logic moves to the deployment and CI would test something else) and an admin or init container that installs the apps (a second place for the app list).
