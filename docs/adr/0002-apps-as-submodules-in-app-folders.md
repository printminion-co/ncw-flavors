# Out-of-tree apps are submodules in app folders of the server fork

Every app outside the server tree is a git submodule inside an app folder (`apps-<set>/`) of the fork, activated per flavor through a generated `apps_paths` setting. The submodule commit is the pin, so there is no separate lock file, and a snapshot freezes all apps of all flavors. We rejected the app store (not reproducible, allows pre-release apps) and per-flavor pins in the flavors repo (a flavor could not use a forked app while another uses the vanilla one without duplicating sources). Consequences: one pin per source per branch, so a different version needs a differently named submodule; and an app id must exist in only one active folder, because Nextcloud loads the highest `info.xml` version of duplicates and only on a tie the first folder, which makes overriding by folder order unsafe.
