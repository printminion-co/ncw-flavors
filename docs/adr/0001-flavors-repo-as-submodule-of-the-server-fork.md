# The flavors repo is a submodule of the server fork

The server fork carries the flavors repo as a submodule at `IONOS/`, tracking the `v<nn>` branch of the line. A snapshot branch therefore freezes the server, the app pins and the flavor definitions by commit, so one tag reproduces every flavored artifact of a release. We considered keeping the flavors repo separate and tagging both repos at release time; that works but needs two refs to be kept in step, and the cross-repo tagging token would be a single point of failure for reproducibility. The cost of the submodule is that a flavor change needs a commit in the fork to move the pin. Because the pipeline also lives in the fork (ADR 0007), the only token it needs is the same-repo sync token described there.
